Baseline: expanding_mean
========================

Name & Task
-----------
Registry key: expanding_mean
Task type: Ordinal baseline (fatigue_num, 0–5)


Purpose
-------
Participant-specific running mean of all prior fatigue ratings (excluding
current day). Smoother than lag1; often the best ordinal baseline on test.


Algorithm & Library
-------------------
Custom: ExpandingMeanBaseline extends PriorValueBaseline


Source Code
-----------
Classes: ExpandingMeanBaseline, PriorValueBaseline in src/modeling/baselines.py
Builder: build_expanding_mean_baseline()
Prior computation: compute_expanding_mean_prior() in src/modeling/data.py
Benchmark: attaches bundle.y_expanding_train_val / y_expanding_test as __prior__


Input Format
------------
DataFrame = feature matrix + __prior__ column with expanding mean of
earlier days' fatigue_num for the same participant.


Preprocessing
-------------
Prior computed per participant:
  shift(1) then expanding(min_periods=1).mean() on sorted days
NaN on first day of each participant.
Same fallback and clip logic as lag1_fatigue (PriorValueBaseline).


Default Hyperparameters
-----------------------
None.


Optuna Search Space
-------------------
None.


Training Flow
-------------
fit: stores fallback_ from training prior column
predict: fillna(fallback), round, clip to [0, 5]
Evaluated with GroupKFold CV and participant holdout test set.


Prediction & Post-processing
------------------------------
clip_ordinal_predictions after rounding filled priors.


Evaluation Protocol
-------------------
CV and test: MAE, RMSE, R2, QWK
Typical test MAE ~0.84 (best among ordinal baselines in recent runs)


Known Limitations
-----------------
Requires prior days within participant; first day uses fallback.
Still ignores activity features — only uses own fatigue history.
Notebook currently compares ML models vs lag1, not vs expanding_mean
(optional future delta column).
